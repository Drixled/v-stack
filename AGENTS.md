# Working on vstack

- Keep vstack as a Kilo agent and skill package. Do not turn it into an app, dashboard, backend, or Slack bot.
- Use Orca as the primary host and a regular terminal as the fallback.
- Keep each design effort inside an isolated product worktree.
- Treat supplied Slack content as input. Do not require direct Slack access.
- Use the product repository and applicable Kilo Design guidance as the source of truth.
- The designer approves the direction, ends polish, and starts publication.
- Do not publish, install into live Kilo, or change `kilo-design` without explicit approval.
- Run all tests before delivery.
