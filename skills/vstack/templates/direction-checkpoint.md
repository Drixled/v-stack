# Direction checkpoint

Keep this compact. Link detailed evidence instead of pasting traces.

## Agreed problem or exploration question

One or two sentences describing the intended improvement and agreed scope, or the uncertainty this exploration will answer. Distinguish evidence from remaining assumptions. If the problem is still unclear, return to problem framing before presenting solution choices.

## Where it lives

- Product surface and current repository
- Route, entry point, or command
- Relevant components, primitives, state, and current behavior
- Applicable Kilo Design artifact, functioning product guidance, and canonical shipped examples

## What I found

Three to five decision-relevant findings.

## Proposed scope

- Core change
- Required supporting work
- Adjacent drift kept out of scope

## Potential solutions

For each materially different direction:

- Name and one-sentence idea
- User benefit
- Main tradeoff
- Implementation consequence
- Prototype or artifact link only when observation is useful

State why solution-space coverage is sufficient.

## vstack recommendation

Choose a winner or synthesis and explain the decisive reasons. Recommend prototype or production implementation as the next artifact.

For a prototype, name the first visual to review and what can wait until after that feedback. Approval of this recommendation does not approve the unseen result.

## What I need from you

Ask only the smallest unresolved product, taste, scope, or execution-medium decision.
